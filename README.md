# Школьное расписание

Расписание 70 классов из школьного XML aSc Timetables, соединённое с реальной Google Таблицей замен. При первом открытии появляется окно выбора параллели и класса. После подтверждения показывается только выбранный класс, открывается сегодняшний день по Москве. Дни переключаются стрелками и свайпом. Месяц и год выбираются списком над расписанием. Кнопка «Открыть календарь» под полосой дней открывает всплывающее окно с календарной сеткой, выбором месяца и года; нажатие на дату открывает её уроки и закрывает окно. В сетке красная точка означает замены выбранного класса, жёлтая — записи для уточнения. Бело-оранжевый интерфейс, единый шрифт, герб школы и подпись «ЗилАрт 548» под названием в левом верхнем углу.

## Запуск

Сайт работает прямо из репозитория на статическом HTTP-сервере, без сборки. Для разработки со сборщиком используйте Node.js 24 и существующий checkout, создавать worktree не нужно:

```sh
npm ci --cache /tmp/school-npm-cache
npm run dev
```

Production: `npm run build`, затем `npm run preview`. Для проверки публикации из корня: `node scripts/serve_static.mjs . 4175` (сайт под `/all_class/`).

## Выбор класса в браузере

Первое открытие без сохранённого выбора показывает обязательное окно с параллелью и классом. Расписание не отображается до подтверждения. Внутри основного экрана переключателей классов нет; дни, месяцы и календарная сетка доступны как обычно.

Выбор хранится в first-party cookie `all-class-selected-class` на один год, в пределах пути приложения, с `SameSite=Lax` и `Secure` на HTTPS. Повторное открытие и новая вкладка сразу показывают этот класс. Существующее предпочтение `school-class` из старой версии можно подтвердить в первом окне, после чего используется cookie.

Мелкая кнопка «Сбросить класс» внизу страницы удаляет только предпочтение класса и возвращает окно выбора. Сохранённые замены и другие данные браузера остаются. Если браузер запрещает запись cookie, выбор работает до перезагрузки страницы и показывается сообщение, что запомнить класс не удалось. Фоновая загрузка замен не сбрасывает незавершённый выбор в окне.

## Заметки к предметам

На каждой карточке урока есть кнопка «Заметка». Она открывает окно с текстом, сохранением, отменой и удалением. Заметка появляется у всех уроков этого предмета в выбранном классе: день, месяц, номер урока, учитель и подгруппа не ограничивают её показ. Например, заметка к математике 6М видна в другие дни и не появляется у математики 5А. Названия разных предметов, включая алгебру и геометрию, не объединяются; официальное и короткое название английского языка относятся к одной заметке.

При нескольких предметах в одном номере урока в окне выбирается предмет. Черновики сохраняются при переключении предмета до нажатия «Сохранить» или «Отмена»; «Сохранить» записывает все изменённые тексты. Подгруппы одного предмета используют одну заметку. Краткое превью видно прямо в расписании, полный текст — в окне заметки.

Заметки личные, хранятся в localStorage этого браузера под ключом `school-subject-notes-v1`, без срока действия, до 5 000 символов на предмет. Сброс класса и обновление расписания их не удаляют. Очистка данных сайта в браузере удалит и заметки. Между устройствами они не синхронизируются. Вкладки одного браузера обновляют заметки друг друга, сохраняя незавершённый ввод. Ошибка записи показывается в открытом окне; текст не исчезает. Текст выводится буквально, без выполнения HTML.

## Служебные настройки

Кнопки «Источники» в шапке нет. Небольшая ссылка «Для сотрудников» внизу страницы открывает ввод пароля `548.8`, после которого доступны источники, проверка листов и локальный импорт. Доступ действует до перезагрузки страницы или сброса класса; пароль не сохраняется в браузерном хранилище. Это ограничение интерфейса статического сайта, а не серверная авторизация: исходные таблицы остаются общедоступными. Фоновое обновление не закрывает календарь и не стирает незавершённый ввод пароля.

## Как соединяются таблицы

- Базовое расписание — `data/schedule.json`, преобразовано из `от 031126_1212.xml` (aSc Timetables, Windows-1251): 70 классов, 3 504 карточки исходного расписания, 3 394 занятых позиции «класс / день / урок», 4 234 записи с учителями и подгруппами. Предмет, учитель, подгруппа и фактический кабинет берутся из XML; список допустимых кабинетов не подставляется вместо назначенного. Понедельник — суббота, 10 номеров уроков. Русский язык и литература, алгебра и геометрия, история и обществознание отображаются отдельными предметами. Сохранены названия внеурочных и дополнительных занятий.
- Замены — [школьная Google Таблица](https://docs.google.com/spreadsheets/d/1vIOpBDYYJlVAnTNHKAvS8YBsIMK8wjV6HU3EACIqJSs/edit). Фактическая структура проверена: дата, отсутствующий учитель, исходный предмет, класс, урок, кабинет, заменяющий учитель, новый предмет. Два столбца «Предмет» различаются по положению. Причины отсутствия, подписи и оплата в данные приложения не попадают.
- Учебная дата берётся из строки, а не из названия листа. Числовая дата Excel преобразуется напрямую в календарные год, месяц и день, без промежуточного JavaScript Date и с учётом систем дат 1900/1904. Это предотвращает сдвиг на предыдущий день из-за исторических смещений часового пояса браузера. Октябрьские записи, скопированные в ноябрьский лист, остаются октябрьскими. Совпадающие записи между листами и перекрывающимися диапазонами удаляются. Все месячные листы сохраняются в инвентаризации `sheetReports`: название, заявленный месяц, фактические месяцы строк и диапазон дат. В «Источниках» перечислены все листы, включая расхождения между названием листа и датами записей.
- Классы приводятся к общему виду: `5з-з` → `5З`; сохраняется исходное обозначение. Поддерживаются списки `11 ш,э`, пометки `(2 урока)` и диапазоны уроков `3–4`.
- Если номер урока указан, замена привязывается к дате, классу и номеру. Внутри урока ищется исходный учитель. Если ФИО не совпало, но исходный предмет однозначно соответствует одной записи, используется этот предмет с видимой пометкой об отличающемся учителе в источнике. При двух одинаковых подгруппах такое сопоставление не делается.
- Если номера нет, используется однозначное совпадение учителя и предмета на этот день. Для строки `(2 урока)` можно сопоставить два занятия, только если количество подходящих уроков точно совпало. Вакансия может быть сопоставлена по уникальному предмету. Во всех прочих случаях строка показывается как требующая уточнения, без зачёркивания неподтверждённого урока.
- Замена одной подгруппы зачёркивает только её исходного учителя. Замена выделена красным над исходной записью. `отмена` показывает «Урок отменён». Новый кабинет берётся только из таблицы замен; если он пуст, это указано явно.
- Разные замены одной подгруппы считаются конфликтом и требуют уточнения. Классы, которых нет в базовом расписании (например, начальная школа), не добавляются автоматически.

Сохранённый срез `data/replacements.json` содержит реальные записи до **5 ноября 2026**. Для дат без записей интерфейс сообщает об отсутствии данных в таблице, не выдавая это за подтверждение отсутствия замен. Для быстрого просмотра есть переход к последним записям выбранного класса.

## Обновление замен

При открытии сайт сначала показывает сохранённый срез, затем скачивает XLSX из Google. Обновление повторяется каждые 5 минут, пока вкладка видима, и доступно по кнопке. Публичный экспорт и его CORS-заголовки проверены. Доступность Google всё равно зависит от сети и настроек общего доступа.

После успешной синхронизации нормализованные записи сохраняются в браузере. Версия данных и кеша — 4. Каждый срез содержит `scheduleRevision`: версию основного расписания, рассчитанную из SHA-256 исходного XML и применённых подтверждённых уточнений. `sourceRevision` сохраняет хеш самого XML. Кеш и включённый в сайт срез используются только для соответствующей версии основного расписания. Старые v2/v3 и срезы другого XML не применяются, даже если импорт новее или отмечен как ручной; старые ключи не удаляются. Выбор класса сохраняется. Для старого ручного импорта в «Источниках» показано предложение загрузить исходный файл заново для нового сопоставления. Основное расписание и срез загружаются с `cache: no-store`, чтобы кеш браузера не вернул прежние данные. При сетевой ошибке последние данные остаются, а статус сообщает, что обновить не удалось. Более свежий срез приложения может заменить более старую сетевую копию. Ручной импорт имеет приоритет и приостанавливает фоновое обновление; кнопка «Обновить замены» возвращает данные Google, «Сбросить локальный импорт» — срез, включённый в сайт.

В разделе «Источники» можно загрузить оригинальный XLSX со всеми месячными листами или простой CSV по `replacement-template.csv`. Корректные записи сопоставляются, неоднозначные перечисляются отдельно для соответствующих класса и даты; строки без распознанной даты можно проверить в «Источниках». Неопознанный формат файла отклоняется, существующие данные сохраняются.

Обновить срез перед будущей публикацией (из корня проекта):

```sh
npm run sync:replacements
# Или использовать уже скачанный файл:
npm run sync:replacements -- /путь/к/заменам.xlsx
```

Команда использует тот же парсер, что и браузер, сохраняет только нормализованный JSON и сама ничего не публикует. Для обновления основного расписания нужен Python 3 без дополнительных библиотек:

```sh
python3 scripts/import_schedule.py /путь/к/расписанию.xml
npm run sync:replacements
```

Порядок важен: после импорта XML замены сопоставляются с новыми уроками. Импорт проверяет ссылки на классы, учителей, кабинеты и подгруппы, разворачивает карточки на несколько дней или уроков, сохраняет совместные занятия. Неподдерживаемые чередующиеся недели и неверные ссылки отклоняются до записи JSON. Сохраняются только данные расписания, без контактов учителей и персональных данных учеников.

Подтверждено пользователем: **6Е — «Разговоры о важном (ВД)», Котнов К.В., понедельник, 1-й урок, кабинет 3.39**. Эта карточка уже есть в XML. Лишняя неназначенная запись с Поповой Ю.Н. исключена через `data/schedule-corrections.json`; её уроки математики и совместное занятие Котнова у 6З сохранены. Уточнение применяется повторно при импорте только этого исходного XML и проверяет существующую карточку. Хеш основной версии учитывает уточнение, а замены пересопоставляются с ним. Другие занятия без назначенного времени по-прежнему перечисляются отдельно.

## Проверки

Проверяется XML-импорт в UTF-8 и Windows-1251: точные предметы и фактические кабинеты, совместные занятия, подгруппы, длительность, несколько дней, неназначенное занятие и сохранность прежнего JSON при ошибке импорта. Браузерные сценарии дополнительно проверяют исправления 6М и 5А, отсутствие старых данных после миграции кеша и подтверждённое занятие 6Е с Котновым.

```sh
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

Для установленного Chromium: `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:browser`.

Модульные проверки покрывают фактические заголовки, диапазоны, пустые номера, подгруппы, конфликты, дубли, отмены, инвентаризацию листов, выравнивание календаря по понедельнику, февраль, смену года и конкретную замену 6М на 5 ноября: 4-й урок, Шурухина О.С., кабинет 2.24. Браузерные проверки выполняются и для исходных файлов под `/all_class/`, и для готовой сборки: загрузка без внешней сети, реальные сохранённые замены, герб, ручной импорт, Google-синхронизация, сохранение после перезагрузки, выбор месяца и даты, переходы между годами, инвентаризация листов, мобильная сетка, первый выбор класса, постоянный cookie, повторные посещения, сброс, запрет cookie и сообщение о сбое запуска. Регрессионные проверки воспроизводят сдвиг даты при историческом часовом смещении в секундах, три часовых пояса, повторное открытие без сети и устаревший кеш с датой 4 ноября вместо 5-го. Сетевые сценарии CI используют управляемые ответы. Реальная HTTPS-загрузка Google и обработка её ответа проверены отдельно через системное хранилище CA. В облачном Chromium прямой HTTPS-запрос к прокси среды не проходит проверку его сертификата; функциональная проверка с живыми данными передаёт браузеру фактический ответ Google через тестовый маршрут, сохраняя TLS-проверку сетевого запроса. Отключение проверки сертификатов не используется.

## Публикация

Поддерживаются существующие режимы GitHub Pages: `main` → `/ (root)` или Source → GitHub Actions. Файл `.nojekyll` и относительные ссылки позволяют публиковать корень без сборки. Workflow `.github/workflows/pages.yml` собирает, проверяет и при выбранном режиме Actions публикует `dist`. Для других статических хостингов можно использовать корень или каталог `dist`.

Модуль `vendor/xlsx.js` и лицензия сохранены в репозитории, CDN не требуется. После обновления зависимости SheetJS выполните `npm run vendor:refresh` и сохраните изменения `vendor/` вместе с lockfile. Герб в `assets/school-emblem.svg` воспроизведён в SVG по предоставленному изображению.
