# All-Class Android — DEMO 1.0

Android-оболочка создана в ветке `android-app` от `Demo1` (`6d77091717dca46865ca4ca8f832d346f20fcdab`). Ветки `main` и `Demo1`, настройки GitHub Pages и рабочие файлы веб-интерфейса не изменяются. Это debug-сборка для демонстрации, не релиз для магазина.

## Состав

- Название: **All-Class**, applicationId: `ru.zilart548.allclass`.
- Версия: `1.0-demo`, versionCode: `1`.
- Capacitor Core / CLI / Android: `8.6.2` (закреплены в lock-файле).
- Node.js 24, JDK 21, Gradle Wrapper 8.14.3, AGP 8.13.0.
- Android SDK 36, Build-Tools 35.0.0, minSdk 24 (Android 7.0).
- Минимальный WebView: 108; на старых телефонах необходимо актуальное совместимое обновление Android System WebView.
- Окно приложения без браузерной адресной строки и ActionBar. Android-иконки и системная заставка используют существующий `assets/school-emblem.svg`.
- Локальная оболочка, расписание, сохранённые замены, видео и XLSX-парсер входят в APK. Production `server.url` отсутствует; origin стабилен: `https://localhost`.
- HTML/CSS, анимация, календарь, выбор класса, заметки, импорт и модель замен сохраняются из Demo1. Демонстрационные события 9Ц по-прежнему относятся к 20.11.2026.
- Единственное явно запрошенное приложением разрешение — `INTERNET`. Геолокация, камера, микрофон, уведомления, аккаунты, аналитика и платные сервисы не подключаются. Резервное копирование данных приложения отключено (`allowBackup=false`).

## Скачать APK через GitHub Actions

1. Откройте https://github.com/ivangusarov386-lab/all_class/actions/workflows/android-debug.yml.
2. Выберите успешный запуск workflow **All-Class Android DEMO debug APK** для ветки `android-app`.
3. В разделе **Artifacts** скачайте `All-Class-DEMO-1.0-debug` и распакуйте ZIP.
4. Установочный файл: `All-Class-DEMO-1.0-debug.apk`. Рядом находятся SHA256SUMS.txt и метаданные APK.
5. Перенесите APK на Android и разрешите установку из выбранного источника, если система запросит. Откройте All-Class.

Сборка автоматически запускается при push в `android-app`. Workflow выполняет чистую установку npm-зависимостей, модульные тесты, Vite build, Capacitor sync, проверку локальных ресурсов, Gradle assembleDebug и проверку подписи APK. Он не публикует GitHub Pages. Артефакты сохраняются 30 дней.

## Запуск в Android Studio

1. Установите Node.js 24 и Android Studio Otter 2025.2.1 или новее. В SDK Manager установите Android SDK Platform 36, Build-Tools 35.0.0 и Platform-Tools.
2. Откройте checkout ветки `android-app` и выполните:

```sh
npm ci
npm test
npm run android:sync
npm run android:open
```

3. В Android Studio установите Gradle JDK **21**, дождитесь синхронизации Gradle, выберите конфигурацию `app` и debug build variant.
4. Подключите телефон с включённой USB-отладкой либо запустите эмулятор. Нажмите **Run**.
5. Для получения APK в IDE используйте **Build → Generate App Bundles or APKs → Generate APKs** (название пункта может отличаться между версиями Studio).

При открытии вручную выбирайте каталог `android/`. После каждого изменения веб-части сначала выполняйте `npm run android:sync`: это пересобирает `dist` и копирует актуальные ресурсы в Android. Скопированные ресурсы и local.properties не хранятся в Git.

Сборка из терминала Linux/macOS при установленном SDK/JDK:

```sh
npm run android:debug
```

На Windows после `npm run android:sync`:

```powershell
cd android
.\gradlew.bat assembleDebug
```

Результат: `android/app/build/outputs/apk/debug/app-debug.apk`. Для установки через Android SDK Platform-Tools можно использовать `adb install -r <путь-к-apk>`.

## Данные и ограничения DEMO

- Выбор класса и заметки сохраняются существующим кодом в cookie и localStorage собственного WebView приложения. Данные браузерного сайта автоматически в APK не переносятся. Удаление приложения или очистка его данных удалит локальные заметки.
- Используется debug-подпись, а не постоянный release-ключ. APK из разных машин или запусков CI могут быть подписаны разными debug-ключами. При конфликте подписей Android потребует удалить старую установку; это удалит её локальные данные. Для демонстрации не следует хранить единственную копию важных заметок только в приложении.
- Основное расписание и офлайн-снимок включены в APK на момент сборки. Живые замены обновляются существующим запросом к Google при наличии интернета. Обновление включённого основного расписания требует новой сборки; нового сервиса обновлений в DEMO нет.
- Внешние сетевые запросы зависят от доступности Google и настроек сети. Без интернета остаются локальные ресурсы и сохранённые данные.
- Системные Back, клавиатура, Android edge-to-edge, выбор файлов, внешние ссылки, экспорт шаблона, сохранность после обновления и работа на конкретных OEM требуют ручного испытания на устройстве. Успешная сборка не заменяет эти испытания.
- Существующий `xlsx@0.18.5` сохранён без изменения ядра и формата данных. Предупреждения GHSA-5pgg-2g8v-p4x9 и GHSA-4r6h-8v6p-xvw6 из аудита остаются актуальным ограничением до отдельно согласованного обновления. Используйте доверенные школьные файлы.
- Новые функции, нативная регистрация, аккаунты, сервер заметок и фоновые службы не добавлены. Это минимальная упаковка существующего приложения.

## Что проверяет упаковка

`node scripts/verify_android_assets.mjs` сравнивает все файлы Vite build с ресурсами Android побайтно, проверяет включение расписания, снимка замен, XLSX-парсера и MP4, название приложения и отсутствие удалённого `server.url`.

Фактический результат Gradle и APK следует смотреть по завершённому запуску GitHub Actions и его артефакту. Документ не утверждает, что APK прошёл испытания на физическом устройстве.
